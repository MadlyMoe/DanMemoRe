## Implemented source branches

- Explicit native long identity for multi-row partial badge puts; exact two-field shape, original catalog join, player owner, positive safe long and duplicate-ID guards. The shared read path retains malformed/foreign/unknown saved rows and cancels rather than replacing them.
- Merged save candidates validate both selected title fields against the actual owned badge set. Zero unequips a title; it does not remove the badge. A combined badge/title save uses the existing profile/token/request/reply transaction. No schema, grant, native precredit or invented signature was added.
- **Explicit offline preservation policy:** already saved badges cannot be deleted by cleanup or event-clock movement. This is not proof of publisher revocation rules. There is no new private earning ledger; imported rows remain codec-only evidence, not proof of their award conditions.
- Newly observed **type9** saves now bind to the referenced original Abyss season, strict matching-end cutoff, inclusive original rank bounds and the existing earned-ranking receipt's published native record. The merged candidate must match that exact record, including aggregate status; an unissued or forged rank/flag put cannot manufacture a badge. The existing explicit solo-offline ranking policy supplies rank1 only after actual closed participation, native score/processing save/ACK and original prizes committed to Presents. It is not publisher-wide ranking. Already owned rows are not re-awarded or invalidated on clock rewind. Only the native client creates the two-long badge row; no server badge precredit, duplicate gift, extra operation, schema or ledger is added. Existing profile/token/sequence/reply rollback applies to combined title-selection and record saves.
- Shared `captureLocalPlayerInfo` no longer rejects all nonempty badge collections. Valid owned selections retain their original long values. This reaches local PvB, War Game, Under Telskyura, Telskyura Abyss, GVE and Familia-raid details through the existing callers and cache comparison paths; peer handling is unchanged.
- The shared public profile now returns sorted original int32 key-item IDs with positive amount and the master feat flag, independently of the saved processing boolean. Nonfeat key items and zero stock do not enter the vector; long title IDs never enter it. Neither reading details nor reading an inventory initializes or precredits native flags, awards, items or currency.
- Shared key-item reads and merged saves validate the native eight-field shape, actual owner, signed-byte/uint32 widths, original identity/catalog and duplicates. Partial existing-row puts retain all other fields/rows. Invalid or incomplete old imports are retained and cancel rather than being filled with guessed flags or converted into empty successful replies.
- **Explicit offline preservation policy:** already saved true processing flags cannot be cleared or deleted through cleanup or clock movement. A newly observed false-to-true save must be an original feat held with positive amount in the before or merged candidate. Spending its amount does not reset the processing flag. No new ledger, schema or producer credit was added; an imported true flag is still only codec-level evidence, not an independently proved award.

The `badges` object in a save request is not being treated as the `UserTitleBadge` inventory; the implementation uses actual named-table deltas.
